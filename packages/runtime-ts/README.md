# TypeScript runtime migration package

This private package is the independent Node 24 candidate runtime under development. Python remains the default. No production entry point selects this package. The `prototype/` wheel experiment remains separate from package behavior.

```bash
cd packages/runtime-ts
npm ci
npm run typecheck
npm test
```

Tests use Node's built-in TS execution and test runner. Config parity tests import the normal `@nanobot/runtime` package entry and compare private real config files with the Python reference in a separate process; set `NANOBOT_TEST_PYTHON` to an installed project Python if the repository `.venv/bin/python` is unavailable. No runtime code imports or spawns Python. TypeScript, Node typings and node-gyp are development dependencies; SQLite uses the pinned `sqlite3` N-API addon. Its install script obtains a platform prebuild or compiles locally, so development installs require that native setup. A narrow owned N-API session-files bridge is built by the package prepare step, so repository installs also need a C++ toolchain and Python for node-gyp. Release wheels must supply the verified addons and runtime JS dependencies; the earlier built-ins-only wheel prototype does not establish addon distribution.

## Configuration

`loadConfig(path?, options?)` returns a `Configuration` with typed camelCase `data`, canonical `sourcePath`, `runtimeDataDir` and expanded `workspacePath`. File opens preserve symlink/parent-component order; canonical source binding follows dangling symlinks to their missing target, so default saves retain the correct instance owner. `options.home` explicitly selects an isolated instance and its default workspace; it never changes process-global home state. `options.env`, `userHome` and `timezone` make isolated applications and tests independent of the host defaults. `resolveConfigEnvVars(config, env?)` returns a separate resolved configuration when references change, preserving the original templates and OAuth fields. `resolveEnvRefs` implements the lenient single-value lookup. `saveConfig(config, path?)` persists aliases, excludes OAuth credentials, retains explicitly supplied/mutated OAuth request settings, and performs a synced temporary write plus atomic rename while preserving an existing file's mode. Save defaults to the configuration's own source path, so two instances cannot overwrite one global selected path.

The complete Python DTO graph's public fields, defaults, alias choices, constraints and serialization exclusions are exported to `src/config/contract.json` and `types.ts`; the decoder and cross-field migrations execute in TypeScript. This avoids reducing configuration to the shared smoke fixture. Legacy API blocks, MyTool/workspace settings, proxy migration, timezone modes, presets/API preferences, provider aliases and retired selectors are handled at the boundary. Nested environment settings retain file-over-environment precedence. Most root sections use `NANOBOT_*`; the explicit `modelPresets`/`model_presets` validation aliases instead use unprefixed environment roots, matching Python, and the prefixed model-preset root is ignored. Template expansion reads only environment-owned keys, including when a template names `constructor`. Legacy proxy credentials use Python-compatible quoting; proxy validation examines raw authority/path components without WHATWG repair. Unknown DTO fields follow each model's ignore/allow/forbid policy; dynamic channels and custom providers retain their supported data. Config errors distinguish JSON/root/schema/I/O/missing-env failures and retain ordered field locations. Pydantic-specific English error wording is not reproduced.

Regenerate the development-time contract after changing Python configuration models, then review the diff and parity cases:

```bash
uv run --no-sync python -m scripts.export_ts_config_contract
uv run --no-sync python -m scripts.export_ts_config_contract --check
```

Config parsing does not install a process-global SSRF whitelist; execution policy will consume the loaded settings in batch 4. Provider routing helpers, cron schedule construction and gateway settings mutations belong to their later owners. Named-other-user `~name` expansion and native Windows/macOS file-mode/rename behavior are not verified here. The current tests compare representative valid and invalid configurations, including the full default graph, rather than every possible Pydantic coercion combination; new public config behavior should extend the shared parity cases.

## Events, queues and admission

The package exports typed internal `EventMap`/`RuntimeEvent` values, inbound/outbound message types, `MessageBus`, `RuntimeEventPublisher`, `EventSink` and `RuntimeAdmission`. Runtime handle types remain generic so model state stays owned by the later runtime owner. Events are internal trusted values; transport adapters must decode untrusted payloads before publishing. `bus.on(kind, handler)` filters known events (including progress/file-edit and side-channel/command-result subtype relationships); `subscribe` retains catch-all support for the `AgentEvent` union. Known event payloads are checked at publish/sink boundaries; extensions use `extension:<name>` kinds with a typed `payload`, so arbitrary or widened kind strings cannot impersonate known events. `npm run typecheck:events` independently compiles the positive forwarding/extension cases and expected invalid-payload cases.

`publish` awaits local subscribers in registration order, isolates ordinary subscriber failures, and propagates cancellation. Synchronous callbacks do not introduce suspension. `publishNowait` starts on the next microtask and returns a retained task with `promise` and `cancel`; `drain` waits for owned scheduled publications, including follow-up publications started by handlers. Separate publications may interleave, matching Python; there is no global event FIFO. `publishEvent` queues routed output independently of local observers. `consumeInbound` returns a `{ message, release }` claim that registers activity synchronously before removing the message, including before the awaiting caller resumes. Prefer `withInbound(handler, signal?)`, which releases activity after awaited handling or errors. An optional strictly synchronous `consumeInbound(signal?, onClaim?)` hook can register the next owner before dequeue completes; a thrown handoff releases the claim and leaves the input queued. The bus automatically registers queued inbound and scheduled local work with admission; maintenance cannot observe an idle gap between dequeue and dispatch. Paused claims leave the queued item intact. Queued messages retain FIFO order and event identity, and routing metadata is shallow-copied. The outbound compaction text fallback is generated from the existing command catalog; it does not project gateway wire frames.

Node cancellation uses `AbortSignal`: handlers receive the publication's signal and should pass it into asynchronous waits/operations. Queue consumes and admission waits remove cancelled waiters, including a consumer cancelled after wakeup, without losing queued work. A handler that ignores its signal cannot be forcibly interrupted in JavaScript; its scheduled dispatch remains owned until it settles, then rejects cancellation. Drain therefore cannot report idle while that handler is still running. No artificial bus-close operation discards queues: admission pause rejects new inbound work, accepted inbound/output remains consumable, and owners stop producers before draining/disconnecting, as in Python. Drain covers local scheduled dispatch, not network delivery completion or unrelated caller-owned awaited publications.

Admission's synchronous checks, activity count, registered pending-work checks and pause/resume operations prevent an idle-check/intake gap on one event-loop thread. The `withActivity` and `withPausedIfIdle` helpers release their guards after errors and awaited cleanup. These are not cross-process profile ownership locks. The runtime publisher copies turn context and consumes per-session/run latency, runtime identity and ordered usage exactly once on completion. Canonical usage event types and the small reported/sum helpers support these publisher cases; provider normalization/retries remain in batch 2B.

Regenerate/check the outbound fallback after command-catalog changes with `uv run --no-sync python -m scripts.export_ts_bus_contract [--check]`. The shared `test/fixtures/bus-events.json` scenario is consumed by both the Python bus reference test and the Node suite. The Node suite also reuses shared client-event compaction phases while keeping wire projection outside the bus.

## SQLite driver and schema (batch 2A, first increment)

`SqliteDriver.open(path)` selects `sqlite3@6.0.1` (SQLite 3.52.0 on this Linux x86_64 run). SQL executes asynchronously on native workers, not on the Node event loop. One connection serializes write transactions; each snapshot uses a distinct read-only connection with foreign keys and `synchronous=FULL`. Long reads use native `sqlite3_interrupt`, repeated briefly after abort until the native callback settles to cover cancellation before native execution begins. Reads close their own connection before reporting cancellation; write cancellation never interrupts a transaction and is reported only after accepted work settles. `close` rejects new admission and waits for owned operations.

`initializeSchema` checks for future versions before changing WAL, then upgrades the released v1–v6 schema transactionally using `schema.json`, exported from the actual Python migrations. It preserves existing import markers and does not mark a fresh database imported: JSONL import, session location ownership, domain history mutations and recovery remain for the following 2A increments. This is a low-level driver boundary, not a usable session owner yet. Its transaction callbacks must use the supplied transaction/snapshot operations and must not recursively enter the same writer.

Focused tests execute a billion-step recursive SELECT in a child with a hard timeout, observe native `SQLITE_INTERRUPT` (about 31 ms in the initial run), and check HTTP responsiveness while another connection holds a write lock (about 22 ms, with event-loop timers continuing). An aborted accepted write commits after lock release before rejecting its caller. Other checks cover JSON/WAL/transactions, private file mode, foreign keys, read-only enforcement and Python v1 fixture → TS upgrade/write → Python reopen/write → TS reread, preserving provider state, checkpoint, pending inputs, timestamps and generation. Tests use only temporary database paths. Native wheel bundling and other OS/CPU combinations are not verified by this driver increment.

```bash
uv run --no-sync python -m scripts.export_ts_session_schema --check
node --test packages/runtime-ts/test/sqlite-driver.test.ts
```

### Model/display history and ordered ownership (2A second increment)

`SessionRepository` reads and writes Python session rows, private provider continuation state, checkpoint and follow-up side tables without mixing display facts into model messages. Stored datetimes remain strings so existing microseconds and offset identity survive reads/writes; new local timestamps follow Python's naive local session-date format. Saves validate revision/generation, update only changed message suffixes, and retain the private/public metadata separation.

`SessionState` supplies bounded per-key ordering and global barriers, detached owner-issued drafts, three-way draft merging, synchronous metadata commands, generation-aware reset/delete, private transient policies, archival membership and atomic model/display forks. Accepted mutations settle before cancellation reaches the caller; close drains all admitted work. Unordered snapshot reads can observe the last committed WAL state while a writer waits. Metadata commands leave the transcript and activity timestamp intact, protect turn-owned keys through the public update path, and publish cached views only after commit. Deleted keys reject late implicit creation until an explicit get starts a new generation.

`HistoryFact`/`HistoryReader` preserve ordered typed display records, independent history revisions, input-id deduplication, byte/record page budgets, navigation, context-usage boundaries and open-tail sequence identities. Existing compressed graph fields remain readable opaque storage values with their original logical-byte accounting; new inline graph JSON is a Python-readable format. Transport-specific thread projection and model prompt replay assembly remain with their later owners. The shared history fixture is compared against Python's real repository and reader, including both Python→TS and TS→Python paths; owner tests cover concurrent mutations, stale generations, rollback of failed forks, WAL snapshots, capacity, cancellation/drain and temporary data exclusion.

Session location/namespace coordination and complete legacy JSONL initialization are not supplied by this increment. Callers must not treat a schema-only driver as a fully initialized profile; the final 2A initialization/recovery increment owns those gates.

### Namespace and private-file primitives (2A final increment, foundation)

`SessionLocation.open(workspace, sessionsRoot)` requires explicit instance-owned roots and rejects storage inside the agent workspace. It preserves Python workspace identity across aliases and moves, rotates copied live workspaces apart, recovers a removed identity from namespace markers, and rejects symlinked state/identity/namespace markers. Namespace allocation uses the same lock file and actual `flock` exclusion as Python `FileLock` on the verified Linux platform, with asynchronous retry and a bounded timeout.

Node does not expose Python-compatible advisory locking or exact nanosecond timestamp setters. The small owned `native/session_fs.cc` N-API bridge supplies just those operations; filesystem reads, writes and directory sync remain in TypeScript. Exact backup timestamps matter because legacy checkpoint eligibility and forensic backups retain their original file identity. `atomicPrivateWrite` uses private temp files, sync/replace/directory sync and the native timestamp operation. Tests verify nanoseconds exactly and prove Python↔Node lock exclusion, rather than assuming an unrelated directory/POSIX record lock is compatible. The native bridge's Windows/macOS branches and addon wheel packaging remain unverified release gates; only Linux x86_64 behavior is established here. Build artifacts stay ignored and are never committed.

### Complete legacy initialization (2A final increment, import)

`openSessionStore({ workspace, sessionsRoot, ... })` composes the namespace, driver, repository and state owner. Schema upgrades and one-time legacy JSONL import commit together; malformed/conflicting sources roll the schema and imported rows back. UTF-8 records reject duplicate JSON keys at every depth, repeated headers/provider blocks, malformed private state and non-regular/symlink sources. Matching legacy checkpoints use the original source timestamp, message count and session identity; older checkpoints are backed up without replacing newer state.

A durable workspace-source manifest commits with import. Startup verifies complete private backups, exact file timestamps and digests before removing any workspace source, then clears the manifest only after file/directory durability settles. A failed cleanup leaves committed rows and the manifest for restart; changed sources or conflicting backups fail closed. Private sources remain untouched, and completed import cannot resurrect a deleted session. The ordinary factory returns a state owner only after this initialization/isolation gate; a schema-only driver remains a lower-level API. Tests exercise Python reopen, Unicode separators, all-or-nothing rollback, duplicate records, restart cleanup, stale checkpoints and one-time import behavior on private temporary stores.

### Checkpoints, cancellation and recovery (2A final increment)

The owner now distinguishes `prepareInput`, `checkpointView`, `finishTurn` and `restoreInterruption`. A checkpoint commits only its recovery payload and synchronized private provider state, retaining unrelated uncommitted draft edits locally. Completion clears turn-owned pending/checkpoint fields atomically with history. Follow-ups are durably journaled without truncation, replay with admission identity, and are removed only by explicit acknowledgements or committed draft input IDs. Summary checkpoints preserve raw/display history while advancing the model replay boundary; generation/prefix validation rejects stale compaction.

Pure recovery helpers match the Python checkpoint validator, tolerant materializer, pending-interruption closure, request origin and sanitized recovery state. Validation rejects incomplete/duplicated tool chains before continuation is offered. Materialization retains cumulative input identity, avoids legacy tail duplication, preserves only synchronized provider continuation, and converts uncertain pending tools into explicit interrupted results. Startup lifecycle/confirmation and gateway event policy stay with the later loop/adapter owners; these storage APIs do not implicitly enqueue execution.

The recovery fixture is compared with Python for synchronized/legacy final output, model input, completed and uncertain tools, malformed prefixes and distinct equal-text inputs. A real child process is SIGKILLed after checkpoint commit; reopen recovers the final answer exactly once and excludes unsaved draft-only edits. Native read cancellation is also exercised alongside an accepted peer write in the same driver, with `SQLITE_INTERRUPT` and the committed peer row both observed. Follow-up restart/deduplication/acknowledgement, stale generations, incomplete display tails, and compaction boundaries have executable owner tests. Other-platform native locking/timestamp behavior and shipping these addons in wheels remain release gates.

Session JSON currently supports integer tokens only within `[-9007199254740991, 9007199254740991]`. Larger Python integers are rejected before materializing session JSON; they are never silently rounded into a writable session. Legacy import fails atomically without committing the schema/import marker or removing originals, and an existing SQLite record containing such an integer cannot be loaded or edited through the affected session operation. Python remains the reader/writer for those records until lossless arbitrary-integer support is implemented. New writes also reject unsafe integral JavaScript numbers. This is a compatibility limit, not a claim of arbitrary-integer interoperability.

## OpenAI-compatible Chat increment

`OpenAIChatProvider` exposes `chat` and `chatStream` through the normal package entry. Its first increment implements generic Chat Completions request sanitation, configurable base URL/headers/query/body, OpenAI token and temperature rules, text/reasoning callbacks, fragmented UTF-8 SSE and final finish reasons. Tests send real loopback HTTP requests from both the Python public provider and TS, including CRLF, comments, byte fragmentation and awaited callbacks. Provider registry specializations, OAuth and Responses are outside this generic adapter. Tools, usage and failure/cancellation ownership are described below. This adapter is not selected by the production gateway.

The tool/usage increment adds indexed interleaved tool fragments, legacy `function_call`, awaited tool deltas, unique missing/duplicate IDs, provider/function extras, and trailing usage-only chunks. Newly generated arguments use ordinary JSON parsing without repairing malformed executable input; malformed/null strings stay strings, empty input becomes `{}`, and valid scalar/array shapes remain available for tool-boundary rejection. Historical request replay alone repairs object-like JSON with pinned `jsonrepair` and coerces non-object history to `{}`. This repair library is separate from Python's `json_repair`; tested object-repair examples match, but arbitrary malformed-history equivalence is unverified. Usage preserves explicit zero caches, field precedence, hidden totals and the canonical reported usage shape. This does not port estimated usage, aggregation services or provider-specific request overrides.

The final 2B increment returns structured provider errors and exports `isTransientChatResponse`, preserving explicit retry hints, 429 billing/quota exclusions, status/kind classification and retry durations. Physical `chat`/`chatStream` calls do not retry; retry scheduling and partial-output guards belong to the caller's later execution owner. Streaming idle time is renewed by each parsed SSE event (including reasoning and usage), not by comments or raw bytes, and callback time is excluded. Default idle is 90 seconds, capped at 3600 seconds for `NANOBOT_STREAM_IDLE_TIMEOUT_S`; non-stream request reads use `NANOBOT_OPENAI_COMPAT_TIMEOUT_S` (120 seconds by default). Explicit positive finite millisecond options support isolated tests and callers.

A finish reason is required before a streamed result succeeds. EOF, transport interruption and callback errors cannot yield successful partial output; the first accumulator parse error is deferred so later live callbacks and transport errors retain Python's priority. `AbortSignal` rejects cancellation and closes the fetch stream; callbacks receive that signal as their second argument. JavaScript cannot forcibly stop a non-cooperative callback: its promise stays owned, and `close()` aborts active work and waits for accepted callbacks to settle. Close is terminal for this TS instance. Real loopback tests verify read/callback cancellation and socket closure; synthetic native cleanup-failure injection and other-platform networking behavior remain unverified. Error diagnostic text is transport-specific; structured metadata, public content/tool deltas and successful results are the compared contracts.

Fresh tool argument parsing follows Python `str.strip` whitespace, including NBSP/NEL/control separators and excluding BOM. Integer JSON tokens beyond the safe JavaScript integer range retain the exact original argument string instead of creating rounded executable parameters; this applies to both ordinary and assembled streaming calls, independently of historical replay repair. Python's arbitrary-precision object result is intentionally not reproduced at this boundary until a lossless typed representation exists.

Without a configured proxy, local endpoint redirect behavior follows the Python Chat provider: localhost, host.docker.internal and Python's private/loopback IP ranges return redirect responses instead of forwarding the request. Non-local URLs retain normal redirect handling. The local-IP classifier includes reserved/documentation ranges and Python's exceptions, with IPv4-mapped IPv6 classified by its IPv4 address. Two loopback ports verify that a local 307 never delivers synthetic request content or custom headers to the destination; range tests compare against the current Python oracle without contacting those addresses. Explicit proxy support remains outside this adapter.

## Agent execution (batch 3)

`AgentRunner.run` accepts a typed model boundary, injected `AgentTools` definitions/validation/execution, detached initial messages, limits, events and an awaited checkpoint callback. It covers deterministic model → tool → model rounds, safe-adjacent tool concurrency, iteration exhaustion with a no-tools final request, blank-reply finalization, tool-capable finish reasons, original tool argument history, model request/text/reasoning/tool events, and cumulative reported usage. Python runner prompts are generated by `scripts/export_ts_agent_contract.py` (`--check` verifies them). Test tools have no filesystem, network or process effects; real execution adapters and policy remain stage 4.

Cancellation retains ownership of models/tools until they settle, rechecks cancellation before further work, records actual accepted tool results and explicit unknown outcomes, and awaits the final checkpoint before propagating cancellation. A failed pre-tool checkpoint prevents execution. Prepared model requests are checked against the context window minus output reserve and Python's 1024-token safety buffer, using the conservative Python UTF-8 fallback or an injected counter. `prepareRequest` can further adapt the model-only request under the same context limit. The following execution components remain private candidate APIs; no production gateway is selected.

`RetryingAgentModel` now supplies the ordinary Chat execution retry owner: four standard attempts, bounded persistent identical-error retries, provider delay hints, retry status/wait/exhaustion events and abortable waits. Visible content prevents connection-error retries; timeout recovery either starts a caller-supplied new stream segment or suppresses subsequent callbacks, matching Python. Reasoning alone does not disable retries. Nine offline public-Python retry scenarios compare attempts, actual delay choices, callback output and retry events; dependency cancellation and interrupted waits have separate ownership checks. This wrapper does not add provider fallback selection, image-request rewriting or OAuth/native-provider state management.

`ContextBuilder` now builds detached, boundary-preserving transcripts from an agent workspace and a separate project workspace. Project `AGENTS.md` stays project-owned, while `SOUL.md`, `USER.md`, memory and custom skills come from the agent root. Bundled unchanged defaults are skipped, legacy SOUL is replaced, enabled/always/explicit skills and their requirements are evaluated from one discovery snapshot, runtime-context markers stay attached to the fresh input, and temporary sessions exclude saved profile/memory and memory/cron skills. Fixed inputs, archived summaries, media blocks and metadata are compared with the public Python builder; the only intentionally normalized prompt field is the engine identity line (`Python` versus `Node`). Tests capture the first and resumed request through the normal Runner model boundary.

Trusted context templates use pinned Nunjucks with the Python Jinja whitespace options; skill frontmatter uses pinned YAML. `scripts/export_ts_agent_resources.py --check` verifies the copied templates and tracked skill resources against Python sources; the developer exporter requires Git, while the installed runtime only reads package resources. Ignored generated documentation is excluded from this source export. Complete installed skill-reference generation, activation-verified plugin discovery and CLI-app alias sourcing remain later distribution/plugin work; typed plugin documents/aliases can be supplied at the skills boundary.

`AgentContextGovernor` now owns the accepted-history/pending-delta boundary, model-only cleanup and context-aware user merging. It removes placeholder/malformed/orphan history, backfills lost tool results, bounds model-facing tool output and preserves runtime-context suffixes, hidden inputs and provider-state boundaries. On pressure it awaits an injected history summarizer, rebuilds the system prefix, verifies the complete request and records a portable summary boundary while leaving accepted raw history intact. Only pending oversized `read_file` results may receive the same durable notice after the replacement request fits. Matching provider usage remains authoritative; a non-positive input budget fails before a model request. The default estimator remains the explicit conservative UTF-8 fallback; callers may inject a provider/tokenizer counter. No real summarization model is selected by this package. Tool-result file offload and provider-native compaction remain separate later capabilities.

`sessionModelHistory` now supplies the separate model replay view: command and summary-boundary filtering, legal tool-call starts, visible-user count/token windows, input attribution, legacy CLI breadcrumbs and runtime-context/public projection follow Python. It keeps persisted messages detached. Selected user images use Python-compatible SHA256 attachment references in an explicit private data directory; replay verifies IDs and bytes, marks replayed images and returns the established unavailable-image text on missing/corrupt data. Tests cover Python → TS and TS → Python image persistence/replay and normal session history projections using temporary data roots. This is storage/context preparation; no image generator, external model or real tool is enabled.

`AgentLoop.processDirect` and `processMessage` now connect captured runtime settings, ContextBuilder, the Runner and the ordered session owner. The loop serializes accepted calls per session while permitting independent sessions, persists prepared inputs/checkpoints/final rows before returning, preserves tool-call/result boundaries and reported usage, and rejects late-generation checkpoints before tool execution. Temporary direct turns use an isolated non-persistent key and discard its cache without touching the durable parent. `close()` owns submitted direct work; injected stores/models retain their external owners. A real SQLite close/reopen test compares the next captured request and stored messages with Python's public direct loop using only a substitute model/tool. Bus intake and queued follow-up injection are described below; transport acknowledgement remains an adapter responsibility.

The loop now tracks accepted job cancellation separately from per-session ordering. Explicit `stopSession` drains real model/tool work, materializes its latest checkpoint, clears the pending turn and acknowledges follow-ups accepted before the stop. Shutdown `close()` aborts and drains by default while preserving durable pending/checkpoint/follow-up records for confirmation after restart; `close({cancel:false})` only drains. A model that suppresses cancellation remains owned and keeps maintenance busy until it actually settles. `scanRecovery` is a read-only candidate query that never executes a model/tool, and `restoreSession` serializes fresh-draft restoration under the same session queue so concurrent calls materialize one checkpoint. It rejects stale generations and discards malformed checkpoint payloads before interruption recovery. This is the core storage/execution seam, not the WebUI recovery coordinator or its authenticated action protocol.

`scanRecovery` now issues process-local, single-use continuation tickets tied to the current generation and private transcript/metadata snapshot. `resumeSession` requires explicit confirmation, rechecks that snapshot inside the session queue, restores completed tool results once and preserves the original request origin. Its model-only continuation prompt is excluded from durable transcript/checkpoint rows. A successfully accepted user input in the same durable generation aborts active recovery and waits for physical settlement before reading the next draft. Pre-cancelled inputs, rejected generations, temporary scopes and failed journal writes do not supersede recovery. Final-response checkpoints offer restoration only. Tickets intentionally do not survive process restart; a fresh scan is required, and authenticated WebUI recovery/delivery remains the adapter responsibility.

The loop cancellation integration also uses an independent native SQLite writer lock: shutdown waits for an already accepted checkpoint write, keeps admission busy while the lock is held, starts no tool after cancellation, and reopens with the accepted input plus its interruption checkpoint intact. This verifies the ordered owner/Runner boundary against real SQLite contention rather than substituting the storage implementation.

`AgentLoop.run` consumes normal bus claims, dispatches independent sessions while preserving per-session order, and enqueues completed replies through the outbound bus. The claim remains held through outbound enqueue, including the dequeue/admission handoff. Stopping intake drains accepted turns; closing the loop wakes an empty consumer and applies the selected cancellation policy. Turn failures can be observed through the injected intake error callback. Queued-input journaling/injection and `/stop` handling are described below. Other commands and transport receipt acknowledgement remain outside this core entry point.

Accepted durable websocket/session-message inputs now start an ordered follow-up journal write independently of the preceding turn's completion. The queued task retains admission ownership and waits for that accepted write to settle even after cancellation. Its journal ID is acknowledged only with the prepared input commit; shutdown leaves unexecuted queued inputs recoverable after reopening. Other channels retain the Python no-journal rule, and temporary calls do not create durable follow-up records.

`AgentRunner` now accepts typed, already-converted injection snapshots before ordinary requests and after terminal responses when the ordinary iteration budget permits another request. It appends the complete accepted user-message snapshot without rewriting raw history, retains the preceding answer, emits a resuming stream end, and leaves late inputs untouched at the iteration limit. An independent terminal callback can supply terminal-only inputs; conversion/queue rollback remains owned by the caller. Three public Python Runner oracles compare actual next requests and raw transcripts for before-request, after-answer and exhausted-budget boundaries.

Loop inbox injection is now connected for bus-dispatched inputs and explicit `allowInjection` calls. It converts one finite FIFO snapshot with the captured context/runtime, preserves raw input boundaries and stops at non-injectable command/direct-call barriers. Conversion failure leaves the whole snapshot owned by its queued tasks. Injected queued tasks skip independent execution only after their IDs appear in a settled checkpoint or successful final commit; accepted journals remain available on interruption. Normal direct calls keep independent ordered-turn behavior unless callers opt in. Commands are currently barriers, not implemented command handlers; authenticated transport acknowledgement remains separate.

The supported `/stop` control now bypasses the per-session execution tail, cancels active and queued jobs, waits for real settlement and journal acknowledgement, and emits Python's structured `command_result` with `stop.done` and outcome `stopped`. A stop tagged with a replaced generation cannot cancel current work. Stop operations themselves remain owned by loop drain/close. No model or tool is invoked for the command, including idle sessions; localized receipt rendering belongs to the consuming channel adapter.

Runner usage accounting now replaces omitted or all-zero usage with an explicit offline UTF-8 estimate for successful content/tool responses, counts usage-free errors as completed zero-token requests, and preserves positive reported usage and mixed reported/estimated totals. Four normal-entry Python Runner oracles cover those cases, including tool-call output. The default remains the documented byte fallback; a supplied prompt counter can match a provider/tokenizer estimate without enabling an external model.

Malformed tool names are removed before execution or persistence. If every call in a tool-call response is malformed, the Runner makes one corrective request with the Python-exported instruction, then one request without tools if necessary. Those physical requests stay within one ordinary iteration and one aggregated usage round; corrective prompts are not added to durable history. Public Python oracles compare the actual two- and three-request sequences, tool selection, final transcript and usage totals.

Batch 3 verification and remaining boundaries are recorded in the [migration review gate](../../docs/typescript-runtime-migration-plan.md#batch-3-evidence-and-review-gate). Network delivery acknowledgements and authenticated UI recovery are adapter capabilities; the core only establishes durable turn/checkpoint ownership and outbound enqueue. Python remains the default while this stage awaits independent review.

Follow-up acceptance can return an owner-issued generation receipt through `acceptFollowup`; the existing `queueFollowup` ID-only API remains available. Stop captures that accepted generation before cancellation/drain and passes it into transactional acknowledgement, so a reset and new-generation journal cannot be consumed by an obsolete stop. The acknowledgement API also accepts an expected generation for callers that already hold that scope.

Corrective and finalization instructions now have a separate transient model-request projection. Context checks include their full wire text, but accepting that request advances only the canonical transcript boundary/projection; its reported context count is not reused as a measurement of the shorter canonical view. A corrected valid tool call therefore remains paired with its real result in the next request and after reopening, without replaying the single-request repair instruction. The Python oracle currently retains that repair text in its third wire view; these regressions compare the first corrective requests, completed tool work and raw transcript with Python, and independently enforce the migration review's explicit no-repair-text rule on subsequent TS requests.

Loop intake uses that synchronous handoff to register accepted jobs and routed deliveries before an awaiting consumer resumes. Same-tick `close({cancel:false})` therefore drains the already claimed turn and any blocked error callback; `close` also waits for intake cleanup itself. The intake completion latch is separate from the work set it drains, avoiding a self-wait. Tests cover both successful final outbound enqueue and error cleanup, followed by an idle admission check.

## Execution workspace policy (batch 4, in progress)

The first policy boundary exports `resolvePolicyPath`, `resolveAllowedPath`, `isPathWithin`, `isPathAllowed` and `requirePathWithin`. Resolution walks physical symlink components before parent components, enforces root containment before strict missing-target errors, and distinguishes exact-file grants from directory grants. Exact grants cannot authorize children, directories or logical symlink aliases. The hard-boundary instruction matches Python; an explicit home argument keeps isolated callers independent of process-global home selection.
